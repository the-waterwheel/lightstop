# 自动测距兼容调整（2026-10-05）

实现基于最新 debug 对应的 `d3e466b`，保留 Android 9 / API 28 最低版本与现有相机采样流。

## 回归原因

此前连接的 vivo V2405A 主摄提供对焦读数，但声明距离未标定。旧版 `66dbf50` 的帧处理仍会计算读数倒数；`6c275e7` 开始在每帧执行能力检查，并限制低质量距离参与闪光计算，因此这类设备无法继续显示可用的自动结果。用户已说明旧版曾用已知距离核对，且接受较大误差。

## 当前行为

- 已标定和近似标定的读数继续使用现有距离及误差计算。稳定但置信度低、误差范围较宽的对焦读数可作为约值参与闪光估算。
- 未标定、缺少标定声明或无法识别物理镜头时，使用对焦读数倒数的兼容估算。至少五个成功对焦且镜头稳定的样本，按中位数及 MAD 去除波动影响；窗口为两秒，最多保留十个样本。
- 未标定估算限于 0.05–30 米，标为 `FOCUS_ESTIMATED` / LOW，不生成未经验证的物理误差区间，不与可靠的运动距离融合；独立的有效运动距离优先使用。
- 闪光工具、距离旋钮显示 `≈`，估算产生的闪光结果显示“估算”。仍拒绝过期、无效数值和未解决的距离来源冲突。无穷远、失焦或暂时没有稳定样本保持等待状态，不因精度差而关闭 Auto。
- Auto 选择会启动采样，包含尚未“应用到测光”的工具页面；关闭未应用的页面会释放采样。后台和相机重启不会主动弹提示。
- 固定焦点、缺少距离结果且没有可运行的独立测距来源时才显示不可用。Auto 字样变灰，每次用户明确切到 Auto 后至多显示一次原因提示，仍可重试或选择手动距离。

未标定读数的单位不由 Android 保证；本兼容路径是用户选择的粗略估算，不能把稳定性或工程置信度解释为绝对测距精度，也不能保证任意机型的读数倒数都接近真实距离。

## 验证

常规命令：

```powershell
.\gradlew.bat --offline :app:testDebugUnitTest :app:lintDebug :app:assembleDebug --console=plain
```

测试包含未标定/缺少物理 ID 的估算、所有标定类别的 3 fps 采样、过期结果、异常读数、运动来源优先、低精度闪光计算和不可用提示去重。

最终常规验证通过：537 项单元测试，零失败；debug APK 构建成功；Android lint 为零错误、65 条警告。

可选 UI 命令：

```powershell
.\gradlew.bat '-PuiPreview=true' '-Pandroid.useAndroidX=true' :app:testDebugUnitTest --tests '*AutomaticDistanceUiPreviewTest'
```

两个 UI 用例已通过：未应用页面的 Auto 选择通知及浅色/深色的生产 Canvas 渲染。四张预览位于被忽略的 `app/build/ui-preview/auto-*.png`，已人工检查。预览中的距离为测试数据，不代表设备实测精度。

本轮 ADB 未检测到连接设备，因此未安装新 APK，也未验证修改后在 vivo 上的真实距离。构建产物为 `app/build/outputs/apk/debug/app-debug.apk`。
