# 中性评价测光 V1：反转片基准设计

设计日期：2026-10-15。本文保留最初方案及参考资料；用户确认后，已在独立分支实现。2026-10-17 正式入口更名为“全局测光”，仅在 Normal 有效；进入 Zone 默认按角度测光，返回 Normal 恢复全局。内部保留 `AVERAGE` 标识以兼容旧设置。最新实现、与初稿的细节差异及验证边界见 [实施记录](AVERAGE_METERING_IMPLEMENTATION_2026_10_15_ZH.md)。

## 1. 目标与核心决定

新增“平均测光”（初稿暂名“评价测光”）。其定义是：**在用户当前可见画幅内，求面积等权的稳健曝光基准，只允许有限的亮部保护偏移。** 首版面向反转片的日常曝光，不判断拍摄者想突出谁。

它包含两个亮度统计量和一条曝光修正规则，不建立场景类别、样本库或学习过程。计算不依赖照片训练集、标注主体、人脸、肤色、天空、距离或相机厂商。

“中性”具体指：相同亮度占比得到相同结果；不因主体位于中央、上方或边缘改变权重；普通反差下不固定欠曝/加曝；高反差时只作有上限的亮部照顾，保留用户曝光补偿的决定权。这是一种明确的统计基准，不是声称能从反射光唯一推断正确的创作曝光。

现有点测、中央重点、角度测光保留各自含义。新算法复用项目的采集和校准流程，另建全画面统计与纯数学决策；不向 `CameraController` 增加算法状态、规则和图像处理职责。

### 2.1 尼康、佳能公开权重的核查边界

[尼康对 FA 的官方技术回顾](https://imaging.nikon.com/imaging/information/chronicle/history-f3/index.html)公开了五分区、极端亮度处理、反差和位置线索，以及在四种曝光求法间选择的思路；还明确说明处理程序来自超过一万组实拍数据的处理。因而它不是一个只需抄下五个固定权重就能完整复现、也完全不依赖样本开发的算法。

[尼康公开专利 EP0505205A1](https://patents.google.com/patent/EP0505205A1/en)列举了平均、中心、高亮重点、低亮重点等求法及模糊组合，并讨论硬分类边界造成读数不稳定。这可用来理解决策原理，不能直接当成某款上市机的完整固件参数。

[佳能 EOS 650 官方档案](https://global.canon/en/c-museum/product/film122.html)、[EOS 7 官方档案](https://global.canon/en/c-museum/product/film224.html)及 [EOS-3 官方规格](https://www.usa.canon.com/support/p/eos-3)可以确认分区评价及与对焦点的联系。检索到的 Canon EOS 50/ELAN II 服务资料还展示主区、中间区、外围区的权重分组，但本次 PDF 全文读取失败，未据此确认其完整数值和计算链。

本次能确认部分分区、分组、方法与公开专利；不能确认存在一套适用于所有胶片尼康/佳能的公开固定权重表。对于本项目，复刻对焦点、背景和场景分类反而会增加拍摄意图假设，故不作为 V1 目标。

### 2.2 为什么使用反转片基准

[Kodak 的 E100 FAQ](https://www.kodakprofessional.com/sites/default/files/wysiwyg/E100%20FAQs%20PDF%202024.pdf)强调反转片曝光容错较窄；该资料中的约 ±半档是整体曝光误差的提示，不是胶片只能记录一档场景反差。

V1 因此优先保持准确、可重复的中间基准，并在亮端压力出现时适量减少曝光。不执行固定减半档，不为填满手机 RAW 而自动增加曝光，也不自动抬升暗部。

## 3. 输入、坐标和光度定义

### 3.1 使用现有采集流程

继续使用 `RawLightMeter`、`CompatibleLightMeter`、精确时间戳配对、来源独立校准、帧数和恢复机制。首版仍是按键完成一次测量，不新增实时 AE 闭环、常驻 RAW、包围曝光或 HDR。

分析对象是当前画幅、方向和电子变焦确定的可见区域。画幅外数据权重为零；画幅内按真实面积计权。分区可用于均匀分配采样与质量诊断，但不赋予中央额外曝光权重。

RAW 使用完整 Bayer 单元稀疏采样，扣黑电平、按白电平归一化，并沿用项目可用的颜色变换获得线性亮度。**先获得每个局部样本的亮度，再做亮度分布统计**；不把四个通道各自中位数的合成值当作全画面亮度分布。

处理后来源使用已有 RGB 重建、tonemap/传递函数解码和来源响应校正。两类来源输入相同的决策模块，但 ISP 局部处理留下的不确定性仍需保留。

### 3.2 每个样本的 EV100

对具有有效光度信息的样本 j，在第 k 帧中定义：

```text
C_k = log2(N_phone,k² / t_phone,k × 100 / ISO_phone,k)
b_k,j = C_k + log2(Y_k,j / 0.18) + calibration_k,j
```

- `Y` 是线性亮度，不是编码后的 YUV Y 值。
- `calibration` 使用该镜头、该来源且当前有效的校准。RAW 常数偏移和处理后亮度相关的响应校正不能混淆。
- 暗角在采样/光度层按位置处理，避免用中心的一个增益修正全画面，也避免重复校正。
- 这里的 `0.18` 沿用项目现有归一化基准，并不是新增“所有物体都应当是灰卡”的场景判断。

以这些 `b` 建立**按画面面积加权的 EV 分布**。如果分区面积或采样密度不同，需要把每个样本还原成它代表的面积；不能让采得更密的区域获得更多曝光权重。

## 4. 两个统计量

记 Q(u) 为上述面积加权 EV 分布的分位函数。定义 EV 域区间均值：

```text
T(a,b) = 1 / (b-a) × ∫[a,b] Q(u) du
```

实际计算在直方图累积面积中完成，分位边界上的桶只计入对应的部分面积。

### 4.1 全画面基准

```text
B = T(0.05, 0.95)
```

即去掉两端各 5% 后，对剩余面积的 EV 求平均。其目的在于让极小的黑洞或亮点不支配整个读数，同时保留大面积明暗组成。白墙、黑色物体、大面积天空仍按其实际面积参与；不因它们形成直方图大峰而主动降低权重。

这是**对数亮度/EV 的稳健中心**，不是线性光通量平均。选择它的理由是：曝光按档数变化，EV 域的明暗偏差更适合做对称平衡。对于等面积、分别在 EV8 和 EV14 的两块区域，基准为 EV11；线性平均亮度得到的 EV 会更偏向亮区。V1 明确采用前者，避免将两种“平均”混为一谈。

### 4.2 亮端参考

```text
U = T(0.98, 0.995)
```

取亮端的一个窄分位区间，而不取全图最大值。最高 0.5% 不参与 U；它仍记录在质量/分布统计中。此举是统一的统计抗离群规则，不是识别太阳、金属、灯泡后作特殊处理。

这个量不等价于“重要高光”，也不保证某个百分比的画面都被保留。它只是稳定、可定义的亮端代表；大面积亮区仍会显著影响它。

## 5. 一条有上限的亮部修正

V1 提议参数：

| 参数 | 初始提议 | 解释 |
| --- | --- | --- |
| 基准分位范围 | 5%–95% | 面积等权、对称截尾 |
| 亮端分位范围 | 98%–99.5% | 不由最高几个像素决定曝光 |
| 亮端参考余量 h | +2.5 EV | 相对基准灰的策略参考，非通用胶片饱和点 |
| 最大自动减曝光 c | 0.5 EV | 限制算法对中性基准的改写 |

决策公式：

```text
delta = clamp(U - B - h, 0, c)
E_recommended = B + delta
R = max(0, U - E_recommended - h)
```

EV 增加意味着外部相机的曝光量减少，所以 `delta > 0` 表示有限的亮部保护。只有 U 比基准高出 h 时才发生修正，低反差场景 delta 为零。delta 永远不为负，因此不会为了把高光“顶到上限”而给低反差画面额外加曝。

R 表示修正之后仍高出这条**策略参考线**多少档；它不是“实际胶片过曝档数”。R 大于零时，说明自动修正已到上限，仍有明显亮端压力。应告知用户，不继续把整幅压暗来满足一个不确定的白点假设。

### 5.1 参数为何不能当作胶片定律

h=2.5 和 c=0.5 都是本项目待验证的初始设计值。不能由 Kodak 的 ±半档曝光容错推导它们，也不能声称它们保证 E100、Velvia 或所有反转片的细节保留。

项目已经有 `FilmLatitudeRange`、`FilmLatitudeRepository.effectiveRange()` 和相对 Zone V 的高低端配置。例如当前库中 E100/PROVIA 100F 的高端参考为 +2.5，VELVIA 50 为 +2。可复用这些数据结构，**无需新增胶片曲线拟合或训练流程**；但库中范围不等于经过本算法验证的厂家实测裁切界线，审计文档也说明部分纬度是类别默认值。

建议 V1 默认使用固定的“反转片参考”基准。只有用户明确选定测光所用的胶片参考时，才取其 h；不能因为在其他工具中曾浏览过一款胶片就悄悄改变本模式。具体型号的精细响应和自动材料切换不进入首版。

## 6. 算法边界与拍摄者的决定权

- 不识别人脸、肤色、天空、雪、夜景或逆光；不因构图位置猜测主体。
- 不把大面积亮/暗区域判为无用背景，也不自动把暗部放到某个 Zone。
- 不追求最大熵、零偏度、最大边缘数或最大数码 RAW 信噪比。
- 不因反转片模式而永久扣除曝光；没有亮端压力时返回 B。
- 保留用户曝光补偿。用户选择剪影、亮调、暗调或主动舍弃亮部时，算法不重新抵消用户设置。

反射式测光无法只凭一幅亮度分布判断白色物体是否应当保持白色，或黑色物体是否应当保持黑色。大片雪景和黑背景仍可能需要拍摄者补偿；V1 接受这个边界，不通过增加场景猜测去掩盖它。

若未来希望算法绝对不改变整体调子，只需使用 c=0 的同一基准作为对照；这是可解释的消融基线，而不是另外开发一种模型。

## 7. 手机测量质量与胶片亮部是两件事

手机 RAW 饱和表示测量信息不足，不表示外部反转片必然过曝；反过来，手机没饱和也不保证反转片能记录所有调子。不能将 `clippedFraction` 直接当作胶片损失率，也不能用手机 RGB 最大通道代替胶片三层感光响应。

低于有效信号范围、被截断或缺少元数据的样本要保留其面积和质量标记。不能先删除它们再对剩下的画面重新归一化；那会无声地改变测光范围。实现时应判断截断是否影响本次实际使用的 B 或 U：

- 若统计仍可使用，不因少量无关的饱和点无条件追加采集。
- 若 U 被饱和截断，应由已有 `RawLightMeter` 使用现成的有界降曝光重拍能力，不沿用“通道中位数没饱和所以所有统计都可信”的判断。
- 若重拍后仍不能可靠估计 U，但 B 可用，返回明确标记的基准读数并提示亮部未确认；不伪造已保护的结果。
- 若连 B 也无法可靠估计，沿用现有测光失败流程，不捏造精确 EV。

原有 `RawExposureRetryPolicy` 为局部中位数设计：只有足够通道中位数饱和才重拍，最多两级、每级降低手机采样曝光 3 EV。新模式复用其资源流程，**不能直接不加区分地复用其触发条件和次数上限**。按用户后续确认，“平均测光”每次再降低 3 EV，逐帧检查并继续重拍，直到高光统计不再截断，或相机已不能继续降低曝光；新模式的统计有效性由独立分析/质量模块提供。用户随后要求局部三种模式也连续重拍，其步长为 5 EV，以当前测光区域通道中位数饱和为依据，最新行为见实施记录。

这些属于测量有效性处理，不改变外部相机推荐策略，也不新增多曝光融合。

## 8. 多帧、性能与最小实现边界

### 8.1 复用既有多帧流程

保留基础 RAW 帧数、单请求在途、精确配对、补帧上限、超时、取消和预览恢复。先按每帧自身曝光参数归一化为 EV，再合并统计；不同手机采样曝光下的 RAW 数值不能直接相加。

B、U 等摘要可以复用现有中位数工具进行逐项融合，再执行一次本节决策。应把它定义为“逐帧摘要的稳健融合”，不要声称它等价于先融合所有像素直方图。计算完成后再作用户界面的档位量化，不逐格、逐帧提前舍入。

首版没有跨测光动作的历史滤波；上次构图不影响本次按键结果。连续预估若以后实现，再独立评估场景变化与迟滞。

### 8.2 统计成本

一次扫描同时形成面积加权 EV 直方图、必要的分区质量和饱和信息。全局直方图必须来自局部样本，不能只用每格一个中位数拼成“直方图”，否则少量亮端面积可能已经被抹掉。

可从约 3.2 万个完整 Bayer 单元、约 1/32 EV 的统计桶宽作为实现预算起点；明确溢出桶与采样面积。这些是拟议预算，不是实测性能承诺。只需全局分布时不建立数百份大直方图，也不调用数百次 JNI。

新模块可暂分为：

| 模块 | 职责 |
| --- | --- |
| `EvaluativeMeteringStats` | 分布、来源、面积、裁切与有效性证据 |
| `RawEvaluativeAnalyzer` / `ProcessedEvaluativeAnalyzer` | 同步借用已有 Image/Bitmap，生成统计；必要时新增单次 JNI 接口 |
| `EvaluativeMeteringAlgorithm` | B、U、h、c 到推荐 EV、delta、R 的纯计算 |
| 现有采集 owner 与薄结果适配 | 继续捕获、配对、关闭资源，转发结果 |

`CameraController` 目标为零算法改动；如果需要透传用途或不可变请求上下文，只增加薄数据转发，不建立新 owner，也不让算法组件持有整个控制器。

## 9. 与现有结果、校准和 Zone 的连接

保留至少这些不同含义的结果：

```text
baseEv100 = B
recommendedEv100 = B + delta
automaticExposureCompensationEv = -delta
highlightResidualEv = R
source / statisticsQuality / calibrationIdentity
```

用户设置的补偿 EC 在推荐值之后应用：

```text
E_used100 = recommendedEv100 - EC_user
```

若套入现有快门/光圈解算，之后继续使用项目已有 EI 换算、闪光和倒易率规则；不把 EI 再加进 `sceneEv100` 一次。推荐值、基础测量与用户补偿必须分开，避免重复补偿。

校准用途只测来源响应，不运行亮部策略；Zone 点位仍测局部亮度，不能写入整幅推荐值。现有 `MeteringFusion` 的校准样本必须继续描述实际的测量与校正关系，不能拿修正后的推荐值作为灰卡校准样本。

YUV/ISP 仍走同一算法，但保留来源与处理后不确定性，不使用新模式名掩盖来源差异。没有实现或无法可靠支持某来源时，要明确报告，不静默退回点测。

界面建议只增加模式入口、读数及必要提示；详细参数留在说明或诊断。出现 delta 可显示“亮部调整 −0.3 EV”，R 仍明显大于零时显示“反差较大”；测量截断则使用“亮部未确认”。不把 R 显示成精确的胶片溢出量。

## 10. 数学示例与验收

以下均为面积分布直接构造的算例，所有数值都是区域 EV100。已在内存中按分位积分公式验算，不是手机测试，也不是曝光准确率样本。

| 合成画面 | B | U | delta | 推荐 EV100 |
| --- | ---: | ---: | ---: | ---: |
| 全画面 EV12 | 12.00 | 12.00 | 0 | 12.00 |
| 20% EV11、60% EV12、20% EV13 | 12.00 | 13.00 | 0 | 12.00 |
| 99.8% EV12、0.2% EV22 | 12.00 | 12.00 | 0 | 12.00 |
| 90% EV12、10% EV15 | 12.17 | 15.00 | 0.33 | 12.50 |
| 各半 EV8 和 EV16 | 12.00 | 16.00 | 0.50 | 12.50 |

最后一例修正后 U 仍比推荐值高 3.5 EV，R=1。算法不会为了达到参考亮端而继续减曝光一档；提示反差，由拍摄者选择。第三例只说明统一面积规则如何对待小亮点，不能推导所有小区域都不重要。

不需要训练数据的验收性质：

1. 均匀画面与既有有效局部测光结果一致。
2. 全部样本 EV 加 s，B、U、推荐值均加 s，delta 不变。
3. 保持亮度面积分布不变而旋转、镜像或移动区域，结果不变；画幅外区域不参与。
4. 改变样本数量或分区密度，在面积补偿正确时不改变结果。
5. 没有亮端压力时 delta 为零；任何输入下 0≤delta≤c。
6. 同一场景换手机采样曝光后，正确元数据归一化结果一致。
7. 不使用截断统计伪造亮部确认，旧回调不能覆盖新会话。
8. 灰卡校准和 Zone 不受自动策略污染，旧三种模式数值回归。

后续灰卡/参考表校准、重复性测量和日常场景对照是验证仪器，不是训练模型。需要分别记录采集、统计、决策与总延迟；在真机结果出来前，不宣称新算法精度或速度已达到某个数值。

## 11. 首版范围

首版只包括：面积等权的 EV 分布、对称稳健基准、有限亮部修正、测量质量与清晰的结果含义。

不包括：语义场景识别、亮区连通分类、自动选择主体、胶片曲线学习、经验拍摄样本库、实时预估、HDR 或重写相机采集策略。本轮没有复制第三方代码；后续按统计与数学定义独立实现，并保留参考出处。
