# 负片普通取景的影调处理（2026-10-05）

用户反馈负片工具的取景画面偏灰。代码检查发现一个跨机型的可能原因：之前只要进入负片工具，就对支持的相机请求固定的标准 sRGB `TONEMAP_CURVE`，替代相机预览模板原本的影调处理。这样有利于反相时近似线性化输入，但原片取景也失去了手机默认的影调 / 反差处理，可能显得更平。原片 GPU 分支直接显示相机纹理，没有额外叠加灰色或默认 1.4 中间调处理。

现在普通、未锁定取景沿用相机预览模板的影调。开始一键反相、手动截帧或锁定相机时，在等待 AE / AWB 收敛期间切换固定曲线；锁定与后续校正期间维持该曲线，保证取样与显示处理条件一致。解锁或会话参考失效后恢复默认取景处理。设备拒绝固定曲线时仍沿用原有回退流程。

“恢复预览”仍只关闭反相、保留校正参数和锁定。因此在已锁定的标定会话里，原片仍来自固定曲线，可能与未锁定取景有反差差异；没有用额外提亮或对比度掩盖这种差异，也没有声称与系统相机软件逐像素一致。现场偏灰还可能受 AE、灯箱或袋面反光影响，本轮没有真实输入可分离这些因素。

修改范围为 `CameraPreviewRequestCoordinator.kt` 的曲线启用条件及 `CameraController.kt` 的准备状态接线。请求日志增加 `filmCurve`，方便实机检查进入时为 false、取样 / 锁定时为 true。此前单台手机的后台恢复现象及 Camera2 `onClosed` 警告继续保留记录，不在本轮扩大生命周期修改。

最终验证：537 项单元测试通过（0 失败 / 错误 / 跳过）；Debug Lint 0 错误、65 个既有警告；Debug / Release APK 构建成功。当前 `adb devices -l` 未检测到设备，不能把这项修改写成取景颜色已实机验收；后续需在同一镜头、照明和构图下比较未锁定取景，并复测首次锁定与单帧反相。
