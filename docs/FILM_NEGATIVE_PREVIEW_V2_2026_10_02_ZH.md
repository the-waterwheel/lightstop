## 使用变化

- 点击“采样中央片基”会先等待 AE/AWB 连续两帧收敛，然后请求锁定，收到相机确认后才采样。
  锁定最多等待 2.5 秒；采样最多等待 3 秒。重复请求、换镜头和关闭会话会使旧请求失效。
- 中央框由 GPU 绘制，框内边界与采样的 UV 宽高 3% 完全一致，共同经过裁切、旋转和镜像。
- 采样只接受明确锁定、曝光/ISO/白平衡增益完整，并与纹理精确同时间戳的帧。
  收集三张不同时间戳、间隔不超过 250ms 的合格样本；读回间隔至少 80ms。
- 单帧要求至少 80% 像素有效，四个象限各至少 75% 有效，并检查全局分位范围和象限中位数。
  三帧颜色必须同时与前一帧、首帧一致，防止缓慢变化累积；这些阈值是测试版经验参数。
- 不支持可靠锁定或缺少必要元数据时，采样失败并提示手调 RGB，预览仍可继续。
- 已采样的片基绑定相机/会话、曝光、ISO、白平衡增益、色调曲线、颜色矩阵和后级感光增益。
  解锁、重建会话或上述状态改变时，清除旧采样，恢复默认片基并提示重新采样。
  手动改动 RGB 后该参考视为人工设置，不继续作为自动采样参考管理。
- 新增“胶片斜率（近似）”滑块；状态文本显示固定 sRGB 输入曲线或相机处理近似模式。

## 输入处理

设备声明支持 CONTRAST_CURVE 且至少 64 个节点时，请求固定、三通道相同的 sRGB 曲线。
节点在暗部更密，使用解析 sRGB 反函数近似恢复线性值；分段曲线插值仍有误差。
只有结果元数据确认实际曲线与请求一致，才显示固定曲线状态。
控制能力按真正打开的相机查询，避免逻辑相机与物理相机控制能力混用。
同步提交被拒绝时恢复模板曲线并重试一次，后续同一会话不重复尝试该控制。
不支持或未确认时继续近似处理；固定曲线也不是 RAW，白平衡、颜色变换及裁切仍影响结果。

## 输出算法

1. 近似反解输入传递函数，计算 `D = -log10(T / Tbase)`。
2. 用通用胶片直线段模型，把密度转换为相对线性亮度。
   `g` 是胶片斜率，`s = max(白点 - 黑点, 0.05)`：

   ```text
   b = 10^(-s/g)
   L = clamp((10^((D - 黑点 - s)/g) - b) / (1-b), 0, 16)
   ```

3. CPU 查找表使用立方根对数编码 `cbrt(ln(1+L)/ln(17))`，减少 8 位表的暗部量化损失。
   GPU 解码，在低精度设备上使用局部展开避免 `exp(x)-1` 的小量相减损失。
4. Gamma 在亮度域调整曲线，再乘 `2^EV`。一档 EV 在最终高光压缩前对应两倍亮度。
5. 在线性亮度域处理灰度/饱和度；亮度高于 0.75 时逐渐压缩高光，同步缩放三个通道。
6. 超出色域时向等亮度灰色压缩色度，最后统一编码 sRGB，避免先裁切某个颜色通道。

胶片斜率默认 0.65，仅是通用起点，不是具体胶卷、冲洗或相机标定。
尚未引入胶片完整趾部/肩部反演、染料串色矩阵或具体胶卷配置；旧曲线参数的观感会变化，
测试时需要重新调黑白点、Gamma 和斜率。固定曲线与经验采样阈值也需真机验证。

## 性能与验证范围

连续参数更新合并为最新值；亮度、Gamma、饱和度、黑白切换只更新着色器参数，
不重建密度查找表。着色器变量位置缓存。仍不创建额外 RAW/YUV 流，不做整帧 CPU 拷贝。

单元测试覆盖相对密度中性化、光学模型白点、EV 倍率、亮度单调性、高光/色域边界、
暗部查找表精度、采样空间质量、乱序到达的精确帧匹配、重复帧、时间间隔、状态变化和缓慢漂移。
CPU 参考测试不替代 GPU 驱动实际执行。当前环境未完成手机上的 EGL/Camera HAL、色彩、
方向、连续进出、温升和耗电验证。

实机重点：先将均匀片边置于框内再采样；对比锁定前后、旋转屏幕后采样、换镜头、切后台恢复，
并检查不能取得稳定片基的设备仍能正常手调 RGB。固定曲线与近似模式各测一台设备。
