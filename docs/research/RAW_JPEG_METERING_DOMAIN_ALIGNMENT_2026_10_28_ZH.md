# RAW与JPEG非线性差异：对当前测光训练的影响及解决方案

日期：2026-10-28。

## 1. 结论

**会影响。当前JPEG参考曝光预训练可以继续复用，但将RAW输入对齐到训练域，是模型真正接入RAW测光前需要完成的一步。** 网络结构可以共用，RAW与JPEG的数值定义和处理链需要适配。

这个问题有成熟的辐射响应标定、逆ISP和跨域训练研究。我们不需要在手机上完整恢复一张“原始RAW照片”；对测光而言，重点是对齐选区内的曝光坐标、区域明暗分布和必要的颜色统计，可以采用很轻的端侧处理。

本文提出的是下一阶段方案；本轮核对代码和资料并记录设计，未改动当前训练配方。

## 2. 当前训练与真实拍摄的差异在哪里

当前实际运行快照的 `metering_features.py` 与仓库代码一致。它先解码sRGB，再在线乘曝光倍数：

```text
当前训练：JPEG → 逆sRGB编码 → ×2^delta → clamp → 776维特征
```

这样已经比直接乘JPEG编码值合理。不过，逆sRGB编码得到的是显示线性RGB，不一定是相机原始的场景线性信号。

把固定白平衡和颜色变换后的RAW简记为R，把sRGB编码之外剩余的色调/增强处理简记为T，暂略噪声和量化：

```text
JPEG = sRGB_encode(T(R))

当前模拟：  2^delta × T(R)
真实改变曝光再处理：T(2^delta × R)
```

T非线性时，这两项通常不同。一个示例：如果某亮度区间的剩余曲线为 `T(R)=sqrt(R)`，RAW曝光增加1档，经过T后的显示线性亮度只增加0.5档；当前合成则直接在T之后增加1档。这个例子说明变化规律可能不同，不是对本项目误差的实测估计。

图像中的固定位置、颜色和局部对比度也可能被ISP改变。因此差异会进入多个特征，不只是全局B：

| 特征 | 可能受影响的处理 |
|---|---|
| 全局B、区域平均EV | 色调曲线、数字增益、响应尺度 |
| 区域标准差、P10/P90、高光与B之差 | 对比度、局部色调映射、HDR |
| R/G、B/G | 白平衡、颜色矩阵、颜色增强 |
| 饱和/低信号比例 | 传感器截断、显示截断、降噪、黑位处理 |

当前对JPEG的验证成绩衡量的是JPEG参考域下的曝光恢复；要知道RAW上差多少，需要匹配RAW与处理流的实测，不能把现有0.586档直接当作RAW误差。

## 3. 为什么这件事可以处理

可以把差异分成三类：

| 差异 | 处理方式 |
|---|---|
| 已知的黑电平、白电平、白平衡、颜色矩阵、全局曲线 | 用元数据和固定运算转换；也可通过响应标定拟合 |
| 未知或随模式改变的曲线、颜色增强、局部处理 | 用条件配置、响应范围增强和真实配对数据微调 |
| 截断、严重量化或多帧合成丢掉的原始信息 | 用可靠性判断、其他曝光或RAW本身提供信息 |

RAW并不因为JPEG处理复杂而失去价值。相反，RAW保留了更直接的传感器信号，曝光变化更容易建立物理关系。我们应让模型的训练和接口适应这一关系，而不是把任意JPEG的观感曲线视为统一物理标准。

标定也不只有“加减一个EV常数”。固定偏移可以修正零点，随亮度变化的响应曲线可以修正非线性。对局部、颜色相关的处理，再增加条件信息或学习适配。

## 4. 相关研究与实现

### 辐射响应标定：多曝光估计曲线

[Debevec与Malik：Recovering High Dynamic Range Radiance Maps from Photographs，SIGGRAPH 1997](https://www.pauldebevec.com/Research/HDR/) 是经典多曝光响应恢复工作。[Columbia CAVE的DoRF/EMoR](https://www1.cs.columbia.edu/CAVE/software/softlib/dorf.php) 提供响应函数数据库和经验模型，可以用色卡或同一场景的不同曝光估计响应。

这类方法适合估计较稳定的全局响应；[OpenCV官方HDR教程](https://docs.opencv.org/doc/doxygen/html/d2/df0/tutorial_py_hdr.html) 已提供 `createCalibrateDebevec` 和 `createCalibrateRobertson` 实现。标定在离线进行，端侧可用查表。

### 相机成像模型：不只是单通道曲线

[A New In-Camera Imaging Model for Color Computer Vision and Its Application，TPAMI 2012](https://www.microsoft.com/en-us/research/publication/new-camera-imaging-model-color-computer-vision-application/) 分析了多台相机的处理行为，提出比传统响应模型更适合颜色处理链的标定方式，用于从sRGB估计RAW响应。这提示我们同时处理颜色与亮度，而非仅修正一个gamma。

### Unprocessing：用现有JPEG构造近似RAW训练数据

[Unprocessing Images for Learned Raw Denoising，CVPR 2019](https://arxiv.org/abs/1811.11127) 分步骤逆转色调、编码、颜色与增益等过程，再构造传感器噪声。这是与“继续使用现有共享JPEG图池”很贴近的方法。

其用途是构造更接近RAW分布的训练样本，不是宣称找回每幅JPEG真实丢失的传感器数据。作者的 [unprocess.py](https://github.com/timothybrooks/unprocessing/blob/master/unprocess.py) 标注Apache-2.0，可作为后续离线合成模块的实现参考。

### ParamISP：处理链受相机参数影响

[ParamISP: Learned Forward and Inverse ISPs using Camera Parameters，CVPR 2024](https://arxiv.org/abs/2312.13313) 将ISO、曝光时间等相机参数用于RAW与sRGB的正反向映射，针对不同参数下ISP行为变化进行建模；[作者公开实现](https://github.com/woo525/ParamISP) 给出了预训练和按相机微调流程。

对本项目的启发是让适配器知道来源、曝光/ISO及相机处理配置。主要借鉴条件化建模和配对训练，不需要把它的完整图像网络放进手机。

### InvISP：可逆处理链与普通JPEG恢复是两回事

[Invertible Image Signal Processing，CVPR 2021](https://openaccess.thecvf.com/content/CVPR2021/html/Xing_Invertible_Image_Signal_Processing_CVPR_2021_paper.html) 重新设计了可逆的正向与反向ISP。它展示了联合设计处理链的潜力；普通手机生成、没有经过该可逆链的JPEG，不能直接套用其可逆性结论。

以上研究有的处理去噪、RAW恢复或成像，不直接给出本项目的测光EV精度；可借鉴的是它们处理输入域差异的方法。外部代码、权重、数据分别按具体授权选择，目前未导入这些实现。

## 5. 推荐给当前项目的结构

建议建立一个明确的“统一测光输入域”，共享后面的776维统计和小网络：

```text
RAW
  → 扣黑电平、按白电平归一化、CFA采样
  → 白平衡与颜色矩阵、镜头阴影/尺度标定
  ┐
  ├→ 统一的线性RGB测光坐标 → 区域统计 → 小型测光模型
  ┘
JPEG / YUV / 预览
  → 范围及颜色编码还原、逆报告曲线
  → 多点响应与必要的颜色/条件适配
```

RAW的归一化首先是黑/白电平和已知设备尺度，不应每帧按自己的平均亮度重新归一化。模型依赖全局B表示当前曝光，逐帧把画面拉到同样亮度会丢掉它要判断的信息。

颜色矩阵、曝光坐标、裁切和质量特征必须有一致定义。尤其要区分“RAW传感器饱和”与“JPEG显示通道变白”：二者不一定发生在同一曝光。适配后的训练需要保留这些来源信息或统一的质量含义。

现有应用已经有可以复用的基础：

- `ProcessedLumaMetadata.kt` / `ProcessedLumaMath.kt` 优先逆相机报告的色调曲线，并支持gamma/Rec.709/sRGB回退。
- `CameraCalibrationStore.kt` 已有按输入亮度插值的多点EV响应校准，不只是单个偏移。
- RAW分支已有黑白电平、CFA、颜色增益/矩阵和暗角相关处理。

目前这些主要服务于现有亮度/EV测光路径；神经模型还读取颜色比、分区分位数和质量比例，接入时要扩展成与其特征一致的输入接口。

若一套解析转换仍留下明显差异，可增加很小的来源适配器，或者分设RAW/预览输入头、共享后面的决策网络。无需先扩大成完整图像网络。

## 6. 下一轮训练数据怎样改

### 6.1 继续复用共享JPEG图池

对现有参考图离线或在线构造近似线性参考：

```text
参考JPEG
  → 近似逆ISP / Unprocessing
  → 线性参考R0
  → R_delta = R0 × 2^delta
       ├→ RAW风格采样、噪声与特征
       └→ 已知或随机化的正向ISP → 处理流还原与特征
```

曝光变化放在场景线性阶段，再生成两种来源的特征。每一组要使用自洽的处理参数；不能任意改变观感亮度后，不加条件或重新定义目标就直接套用旧标签。条件化的曲线、增益或相机参数用于区分这些情况。

同一参考的物理曝光偏移仍提供 `−delta EV` 目标，原照片的曝光取舍继续作为弱参考锚点。这样保留已有图池和训练价值，同时让网络见到更接近部署的输入。

### 6.2 加入真实配对数据微调

少量真实场景可采集同一次曝光或已知曝光关系的RAW和处理图，记录曝光时间、ISO、光圈、白平衡、色调模式和对应ROI。不同曝光组成包围序列，选定一帧或一个区间作为合适曝光。

新增训练包括：

1. 每路各自学习相对选定参考的补偿。
2. 相同场景、曝光与ROI的两路补偿应接近，即 `C_RAW≈C_preview`。
3. 同一场景不同曝光继续满足 `C_delta+delta≈常数`。

跨域约束放在输出或可靠的共享表示上，不要求RAW和JPEG每个像素完全相同。严重截断样本使用质量权重或区间目标，避免强行对齐已经不对应的信息。

若两路曝光不同，先使用已知曝光差换算目标；移动物体、时间错配和不同数码裁切也需要在配对时处理。同一场景所有曝光、RAW和JPEG必须属于同一数据划分。

## 7. 怎么确认问题被解决

建立独立的真实RAW/处理流验证组，比较三个版本：原JPEG预训练、只加解析标定、标定加跨域微调。

| 检查 | 主要回答 |
|---|---|
| 固定ISO/光圈/场景，改变快门 | RAW归一化亮度与已知曝光量是否符合线性关系 |
| 同曝光、同ROI的RAW和预览预测差 | 两种来源是否对齐 |
| 相对人工参考或可信参考的MAE/P90 | 两种来源是否都测得正确，而不只是一起偏 |
| 连续曝光的补偿斜率 | 物理曝光增加1档时，预测是否相应减少约1档 |
| 按明暗、颜色、HDR模式、裁切倍率分组 | 残余差异发生在哪里 |
| 留出相机/镜头测试 | 适配能否迁移到没有参与拟合的设备 |

仍保留当前JPEG固定组作为预训练域对照。两路读数接近和两路都接近正确目标，是两项分别报告的指标。

## 8. 移动端成本

重的逆ISP或多处理链合成优先放在训练电脑上。手机端优先采用现有元数据、查找表、3×3颜色矩阵和小模型，仍只分析每ROI约6,144个位置。

例如拟新增的三个1025项float32查找表合计约12 KiB；在6,144个RGB点上做一次3×3变换约55,296 MAC/次。这些是设计量级，未包含RAW获取、数据复制和特征排序，但不需要运行整幅图的深度恢复网络。

1Hz/3Hz调用仍是每次一帧、一个选区、一次小网络前向。多曝光组和RAW/JPEG双路主要用于训练与标定；常规推理时不要求每次都同时取得RAW和JPEG。

推荐实施顺序：先建少量真实配对验证组定位差异，再改曝光合成位置和统一输入定义，最后进行跨域微调与手机性能测量。现有权重作为预训练起点保留。
