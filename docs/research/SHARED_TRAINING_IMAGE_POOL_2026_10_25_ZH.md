## 2. 合并数据流程，分别保存标签与模型

共同维护一份下载、去重、许可及原图池；两个训练任务分别保存训练配置、派生缓存、标签和 checkpoint。不需要为共享照片而合并两个 Android 应用或把修补网络装入测光应用。

| 层次 | 共享方式 |
| --- | --- |
| 原图与下载 | 沿用现有采集器、图片路径、SHA256 和来源版本；测光不另开下载器 |
| 分组和划分 | 继承原 train/val/test；同图、近似重复、同一场景及全部裁切/增强保持在同一划分 |
| 派生输入 | 测光缓存小图、ROI 和 12×8 分区特征；修补缓存原尺寸纹理裁块；各自有版本和容量上限 |
| 标签 | 修补的缺陷 mask/干净目标与测光的主体、相对曝光偏好、校准 EV 分开保存 |
| 模型与验证 | 分别训练、量化和评价，不能将除尘的 PSNR、mask 准确率当作测光准确度 |
| 清理权限 | 一个共同的原图回收入口；每个任务只清理自己可再生的派生缓存 |

即使图片元数据写有 `kind=synthetic`，也只是除尘任务的合成样本用途，不代表照片本身就是线性 RAW 或有绝对 EV 真值。JPEG/PNG 的亮度和 EXIF 拍摄参数通常不能消除 ISP、色调映射及后期影响。

原有验证/测试集规模很小，且针对除尘建立，不能据此证明测光泛化；后续需增加按场景和设备隔离的测光验证集。不要把已用于任何模型调参的图片重新命名为最终盲测集。将来若用修补模型预处理测光输入，修补模型见过的原图也须纳入测光的泄漏审计。

## 3. 恢复连续任务前必须完成的缓存保留改造

当前 `Registry.reclaim()` 在除尘批次完整提交并用满 passes 后，会删除 `state=consumed AND pinned=0` 的原图；它并不知道另一个测光消费者。用户暂停标记目前仍在，本次没有恢复训练/下载。**恢复前须接入共同保留策略**，不能让旧回收器独立运行。

不要把待共享图简单设成 `pinned=1`：这个字段还影响 register_batch/reconcile 的状态转换，可能使 ready 图片重复进入除尘批次，改变唯一原图计数。硬链接、副本或只读文件属性也不能替代正常消费协议。

建议在数据所有者的下一版本增加独立登记，不修改冻结快照：

```text
consumer_requirements(original_id, consumer, state, manifest_version, updated_at)
  consumer: dust / metering
  state: needed / active / complete / cancelled

may_delete(original) =
  原有除尘批次完成及 passes 校验通过
  AND 不是固定验证/测试或显式保留图
  AND 没有任何消费者处于 needed/active
  AND 没有读取 lease
```

迁移先在事务中为现存 263 张注册 metering 的 needed，再让后续新图默认同时登记两个消费者；哈希、批次、split、旧训练进度不改。回收器在同一锁/事务协议中检查读取 lease 并执行状态迁移，避免“检查后另一方开始读”的竞态。旧版本回收入口必须停用或升级，不能只加一个旧代码不会读取的 JSON 标记。

短期以暂停下载、保留原图为默认；容量不足时停收并报告，不自动放弃 metering 的保留。恢复长期采集时明确原图存储预算或迁往容量充足的公共目录，先复制、核验 SHA256、原子更新引用后再处理旧位置。不能擅自迁移正在使用的文件，也不应让网络盘成为训练必需的单点。

测光何时标记 complete 需要明确：保存有限几个固定网格特征后，无法重新尝试任意数字裁切、选区、分区密度及未来模型。首轮特征和模型尚未固定，保持 needed；只有明确保留了足够的可重建数据或不再需要这张原图，才主动释放。完成一次 epoch 不等于允许删除。

回收改造的验证至少覆盖：除尘完成但测光未完成时文件仍在；两者完成后才可回收；读取中不可删；进程异常后状态可恢复；旧固定验证/测试仍永久保留；磁盘触顶暂停采集；新图自动注册双消费者；迁移不改变除尘批次顺序与唯一计数。

## 4. 这些图片如何用于测光模型

1. **第一阶段，共享原图直接可用**：建立构图/场景分布，人工标记主体、逆光、雪景、夜景、小光源和相对曝光偏好；检查稀疏分区对稠密统计的误差。普通显示照片只能用于显示域和策略研究，不能伪装成传感器测量真值。
2. **第二阶段，相对监督与模拟**：对可信的线性数据模拟曝光、噪声、饱和、裁切和不同选区；比较同一场景的一致性。对普通 sRGB 反变换后做增强，只能视为近似，不能恢复已丢失高光或撤销局部色调映射。用既有规则作老师只能检验规则复现，不能证明优于规则。
3. **第三阶段，准确度验收仍需专用样本**：补充小而覆盖关键场景的手机 RAW/YUV + 精确配对元数据、设备/镜头校准、灰卡/主体参考、包围曝光与摄影意图记录。标签区分绝对测量和曝光策略；保持原场景、设备及最终盲测隔离。

训练增强必须包含数字变焦、画幅和选区变化。先完成与生产路径一致的 ROI 映射，再在 ROI 内重建 12×8 特征；ROI 外高光不得影响结果，暗角仍按物理传感器位置修正。不要只训练整幅中心构图而期望任意选区仍准确。

继续使用前一报告的“分区统计 + 固定规则基线 + 极小权重网络”顺序。12×8 的 MLP 候选约 56,545 参数/56,352 MAC，是未训练的结构估算；共享原图不会增加手机推理输入尺寸。每秒 1–3 次的最终可行性仍取决于手机采集、RAW 读出、统计、量化精度和持续功耗实测，不能由桌面训练速度推断。
