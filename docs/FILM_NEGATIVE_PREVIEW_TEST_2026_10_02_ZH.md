## 使用方式

进入工具后，相机画面自动经过片基补偿和负片转正处理。竖屏参数面板在底部，横屏在侧边，
支持点击把手或滑动把手收起/展开；横屏遵循左右手设置。返回按钮回到工具列表，× 或
系统返回键退出工具。

1. 将负片放在均匀背光前，避开齿孔及片外光源。等待相机曝光、白平衡稳定后，可打开
   “锁定相机曝光 / 白平衡”；不支持锁定的设备会给出提示，仍可调整参数。
2. 片基 R/G/B 始终可以手动调整。可选的“采样中央片基”只在点击时采样中央小区域，
   用于建立初始参考；它不会自动判断哪里是片基，也不会持续追踪片基。
3. 黑点、白点调整密度映射范围，Gamma 调整明暗曲线，“显示亮度（EV）”调整转正后
   的显示亮度，饱和度调整颜色强度。显示 EV 不等于相机曝光补偿。
4. 黑白负片开关会先设定中性 RGB 片基，再输出灰度；仍可调整片基和曲线。重置按钮恢复
   默认参数；重启预览用于相机会话或 GPU 初始化失败后的手动恢复。

参数在同一次 Activity 使用中保留，尚未提供持久化预设、拍照或导出功能。每次重新打开
工具、切后台恢复或手动重启预览后，需要重新锁定相机。

## 当前项目研究与实现

现有应用基于原生 Android Camera2、`TextureView` 和自绘 `MeterLayout`，最低 Android 9
（API 28）。相机输出、请求、显示变换由各自协调器管理；工具入口由 `ToolsCatalog` 和
`ToolsView` 管理。Zone 跟踪及预览健康分析会读取显示画面，所以不能让它们消费转正后的
画面，否则可能影响测光或把调整后的黑色/偏色画面误判为相机故障。

测试版采用以下管线：

```text
普通 Camera2 PREVIEW_ONLY 流
  → SurfaceTexture / OES 纹理
  → OpenGL ES 2.0：三通道密度查找表 + 饱和度 / 灰度
  → 现有 TextureView：继续使用原来的屏幕方向和镜像变换
```

不创建 RAW 或 YUV 图像输出，不将整帧复制到 CPU。CPU 仅在参数变化时生成 256×1 RGB
查找表；每帧 GPU 做相机纹理采样、三个查找表采样及颜色混合。可选片基采样仅回读
16×16 RGBA 小图，来源是未经反相处理的相机画面中央区域（UV 宽高各 3%）。采样剔除
通道值接近 0 或 255 的像素，并使用有效像素的逐通道中位数。

每通道先按 sRGB 近似还原透射量，再计算相对于手动片基的密度：

```text
D = -log10(T / Tbase)
显示值 = clamp((D - 黑点) / (白点 - 黑点), 0, 1)^(1 / Gamma) × 2^显示EV
```

相机 ISP 的白平衡、局部色调映射及通道裁切已发生，因此这属于实时观看辅助，无法恢复
被截断的颜色信息，也不等同于 RAW 扫描转换。默认片基是起始值，需要依据胶卷和光源调整。

NexFilm 的密度思路可以参考；本次 Kotlin 数学、GLES shader 和相机接线均为独立实现，
没有引入其 Rust/Tauri/WebGL 代码，也没有修改本项目许可证。

主要代码：

- `FilmNegativePreview.kt`：参数、密度转换、查找表和片基采样统计。
- `FilmNegativeRenderer.kt`：独立 GL 线程、相机输入纹理、显示输出和资源释放。
- `FilmNegativeToolView.kt`：参数抽屉、手动调节、采样和错误恢复界面。
- `CameraController.kt` / `CameraPreviewRequestCoordinator.kt`：工具会话、相机锁定、帧率和生命周期。
- `MeterLayout.kt` / `MainActivity.kt`：工具入口、全屏布局、跟踪暂停及退出恢复。

## 旧设备兼容策略

- 保持 Android 9 起的支持范围；不依赖 Android 13 的 RuntimeShader。
- 使用 OpenGL ES 2.0 和相机外部纹理，继续使用既有 Camera2 路由及物理/逻辑镜头回退。
- 优先使用设备声明的 30 fps 及以下普通预览范围；请求被拒绝时保留低帧率及不指定
  帧率的回退。实际帧率由设备和曝光条件决定。
- 进入工具暂停 Zone 跟踪、自动测距、测光和显示截图健康分析；退出并释放 GL 输出后
  才恢复普通相机路径，避免转换画面参与测光。
- 切后台释放 Camera2 与 GL 资源，回前台重建。GL 首帧成功及相机/GL 最终失败均有
  界面反馈；失败时展开参数面板，保留“重启预览”入口。
- 当前 APK 包含 arm64-v8a、armeabi-v7a、x86_64。早于 Android 9 的系统仍不在支持范围内。

## 实机验收建议

1. Android 9/10 旧设备与较新设备各测一台，首次进入立即显示转正画面，× 退出后恢复
   普通预览；连续进出至少 20 次，检查黑屏、崩溃和相机占用。
2. 展开/收起抽屉，逐个拖动滑块；检查调节响应、中央参考区和滚动操作。
3. 彩色负片与黑白负片分别测试；将片边放到中央后采样，再用 RGB 手动微调。采样齿孔、
   过曝区域或黑屏时应给出无效提示。
4. 相机锁定后移动负片，观察颜色/亮度是否稳定；不支持锁定的设备应提示而不崩溃。
5. 展开及收起状态下分别旋转屏幕，覆盖 90°/180°、左右手布局和前摄镜像。
6. 工具内切后台再返回，检查预览恢复、参数保留、相机锁定复位；退出后验证普通测光、
   曝光预览和 Zone 跟踪恢复。
7. 工具中应只配置一个预览输出，不创建 RAW/YUV reader；观察 logcat 的 stream profile
   为 `PREVIEW_ONLY`。连续使用 5–10 分钟，记录实际帧率、延迟、温升及设备型号。
